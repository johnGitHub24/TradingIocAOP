TradingIocAOP — 開發專案規格書

本文件為 TradingIocAOP 的唯一主規格書（開發權威）。 主題：以「交易下單／風控」情境示範 依賴注入（DI）、控制反轉（IoC）、AOP、模組化架構。 技術棧：Java 21 · Spring Boot 3.2.2 · Gradle 多模組 · H2/JPA · Spring AOP · JUnit 5 · Mockito · AssertJ。 開發、測試、面試準備均以本文件為準。

第 1 章　系統範圍

1.1 核心功能

  • 交易下單（風控 → 報價 → 落庫 → 通知）。
  • 報價查詢（示範 AOP 快取）。
  • 切面觀測報表（把六大切面的效果攤開）。
  • 手刻 IoC 容器 + 手刻 AOP 的獨立示範（mini-ioc）。

1.2 不在範圍

  • 真實撮合、行情連線、下單回報。
  • 分散式、訊息佇列、快取中介軟體（Redis）。
  • 使用者認證授權。

1.3 技術棧

層 技術
語言 Java 21
框架 Spring Boot 3.2.2
建置 Gradle 多模組（wrapper 8.5）
持久化 Spring Data JPA + H2（in-memory, MODE=PostgreSQL）
AOP spring-boot-starter-aop（AspectJ 註解 + Spring 代理）
驗證 spring-boot-starter-validation
API 文件 springdoc-openapi 2.3.0（Swagger UI）
測試 JUnit 5 + Mockito + AssertJ

第 2 章　模組化架構

2.1 模組結構

TradingIocAOP/  (Gradle 多模組)
├── common/          純 POJO：DTO / enum / 領域模型（零框架相依）
│   └── com.trading.common: OrderRequest, OrderResult, Quote, Side, OrderStatus
├── mini-ioc/        手刻 IoC 容器 + 手刻 AOP（相依 common）
│   ├── annotation:  @Component, @Inject
│   ├── container:   MiniApplicationContext, ClasspathScanner, BeanException
│   ├── aop:         MethodInterceptor, Invocation, InterceptorChain,
│   │                ProxyFactory, LoggingInterceptor, TimingInterceptor
│   └── demo:        OrderPlacer/RiskChecker/PricingGateway (+impl) + MiniIocDemo
└── trading-app/     Spring Boot 應用（相依 common）
    ├── api:         OrderController, PricingController, AspectReportController
    ├── application: OrderService, RiskService, PricingService, NotificationService
    ├── aspect:      六大切面 + AspectRecorder + annotation(@Cacheable,@Retryable)
    ├── infrastructure: OrderEntity, OrderRepository
    ├── dto:         PlaceOrderRequest, ErrorResponse
    └── config:      GlobalExceptionHandler, OpenApiConfig

2.2 模組相依方向

common  ←────  mini-ioc
   ↑
   └────────  trading-app

common 不相依任何人；mini-ioc 與 trading-app 各自相依 common，彼此不相依。這正是「模組邊界」的實踐：共用契約下沉到 common，實作各自獨立。

2.3 層職責

層 職責 禁止
api（Controller） 收發 HTTP、參數驗證 寫商業邏輯
application（Service） 商業邏輯、編排 碰 HTTP、算 SQL 字串
aspect 橫切關注點（記錄/計時/稽核/例外/快取/重試） 混入業務規則
infrastructure JPA 存取 資料轉換、商業邏輯

第 3 章　控制反轉與依賴注入

3.1 手刻容器（mini-ioc）核心流程

  1. 註冊：register(Class...) 或 scan(basePackage) 收集 @Component。
  2. 解析：getBean(type) 遞迴解析建構子參數——相依由容器決定從哪來（控制反轉）。
  3. 單例：每型別建立一次並快取。
  4. AOP：若登記攔截器且元件有實作介面，回傳 JDK 動態代理。

3.2 手刻 vs Spring 對照

概念 mini-ioc（手刻） trading-app（Spring）
元件標記 @Component（自訂） @Component/@Service
建構子注入 反射挑選建構子 + 遞迴解析 自動
容器 MiniApplicationContext ApplicationContext
取得 bean getBean(Class) @Autowired / 建構子
掃描 ClasspathScanner @ComponentScan
工廠式註冊 （未實作） @Configuration + @Bean（見 OpenApiConfig）

3.3 為什麼用建構子注入

  • 相依「必填」且不可變（final），物件建立後即完整。
  • 易於測試（new OrderService(mockA, mockB, ...)）。
  • 可在編譯期發現缺漏，避免欄位注入的隱藏依賴。

第 4 章　AOP 六大切面（trading-app）

# 切面 通知類型 切點 作用
1 LoggingAspect @Around execution(* ..application.*Service.*(..)) 記錄方法進出與參數
2 PerformanceAspect @Around 同上 計時，超過門檻告警
3 ExceptionAspect @AfterThrowing 同上 統一例外攔截與告警
4 RetryAspect @Around @annotation(Retryable) 失敗自動重試
5 CacheAspect @Around @annotation(Cacheable) 方法結果快取
6 AuditAspect @AfterReturning OrderService.placeOrder(..) 成交稽核軌跡

4.1 切面執行順序（@Order）

Logging(10) → Performance(20) → Exception(30) → Retry(40) → Cache(50) → 方法本體
（AuditAspect 為 @AfterReturning，於方法成功回傳後觸發）

數字越小越外層。重試包在快取外、方法本體最內，符合「重試整個含快取的呼叫、快取貼近方法」的語意。

4.2 觀測機制

六大切面都把觀測結果寫入單例 AspectRecorder（由 IoC 容器注入共用），可透過 GET /api/v1/aspects/report 觀察，整合測試亦以它斷言切面確實生效。

## Day 1 — 先看懂「輪子怎麼造」（mini-ioc）

### 上午：跑手刻容器

```powershell
.\gradlew.bat :mini-ioc:run
```

觀察主控台印出的 `[LOG]` 與 `[TIMING]`——那是手刻攔截器在運作。

### 下午：讀四個檔案

1. `MiniApplicationContext` — 看 `getBean()` 如何遞迴解析建構子參數（這就是 IoC）。
2. `ClasspathScanner` — 看「套件名 → 路徑 → 載入 class → 檢查註解」。
3. `ProxyFactory` + `InterceptorChain` — 看 JDK 動態代理如何串起攔截器（這就是 AOP）。
4. `SimpleOrderPlacer` — 看它「不自己 new 相依」，而是建構子被動接收。

**今日記住：** 容器做的事，就是「幫你 new 物件、並把相依塞進建構子」。

## Day 2 — 再看「Spring 幫你做了什麼」（trading-app）

### 上午：跑 Spring 版並下單

```powershell
.\gradlew.bat :trading-app:bootRun
```

啟動成功後先看 Console 框線（health／Swagger／H2／切面報告／首頁），再依連結操作。

用 Swagger、首頁 Demo，或以下指令下單：

```powershell
curl -X POST http://localhost:8080/api/v1/orders -H "Content-Type: application/json" -d '{\"clientOrderId\":\"C-1\",\"symbol\":\"AAPL\",\"side\":\"BUY\",\"quantity\":10,\"price\":190.5}'
```

再看 `GET /api/v1/aspects/report`——logs、timings、audits、retryAttempts 全都有值。

### 下午：讀切面與服務

- `OrderService` — 建構子注入四個協作者（對照 mini-ioc 的手刻注入）。
- `aspect/` 六個切面 — 對照它們與 mini-ioc 手刻攔截器的異同。

**今日記住：** `@Component`/`@Service` + 建構子 = Spring 自動幫你完成 mini-ioc 手刻的那一切。

## 常見問題

| 症狀 | 可能原因 | 處理 |
|------|----------|------|
| `Unsupported class version 52.0` | `java` 指到舊版 JDK | 執行 `. .\scripts\env.ps1` 切到 JDK 21 |
| 快取測試 computeCount 不為 1 | 未清快取/未重置 | 整合測試 `@BeforeEach` 已重置，勿共用狀態 |
| mini-ioc 取 bean 拋「無法指派」 | 被代理的 bean 用具體類別取 | 改用其「介面」型別取得 |
